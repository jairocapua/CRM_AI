# Nimbus CRM — working notes

A **front-end-only** GoHighLevel-style CRM. No backend, no database, no auth.
The goal is a convincing, clickable product that a real backend can later grow
behind without rewriting the UI.

`AGENTS.md` carries Next.js 16's own agent rules (it is regenerated by
`next dev`); Next 16 differs from most training data, so check
`node_modules/next/dist/docs/` before reaching for a remembered API.

## Commands

```bash
npm run dev      # dev server (Turbopack)
npm run check    # format:check -> lint -> typecheck -> build. The gate.
```

Run `npm run check` at the end of every phase. Do not tick a phase off in
`PROGRESS.md` until it is green.

## The one rule: the API seam

Components call `await api.contacts.update(id, patch)` — **never** the store
directly. The mock database lives in `src/lib/mock/` behind `src/lib/api/`.

- `src/lib/api/http.ts` holds `simulate()`, `ApiError`, `ListQuery`, `Page`.
  Rewriting that one file's body to use `fetch()` is the whole backend
  migration; no component changes.
- ESLint enforces this with `no-restricted-imports`: nothing outside
  `src/lib/api/**` (and the mock internals) may import `@/lib/mock/*`, and
  `@faker-js/faker` is confined to `src/lib/mock/seed/**`.
- **Automations are the one thing that is not mock data.** From Phase 8a they
  live as typed modules in `src/lib/automations/` — a developer writes them,
  staff can only view them, and the file is the permission boundary. They are
  still read *through* `api.workflows.*`, for the migration story rather than
  for safety: the registry is pure frozen data, so there is no lint rule
  confining it, but a component reading it directly would be the one place the
  `fetch()` swap could not reach. Definitions reference tags and users by
  **stable key** (tag name, user slug), never by id — seeded ids are
  faker-generated nanoids that change on every reseed — and
  `src/lib/api/workflows.ts` resolves them at read time.

## Non-obvious constraints

- **Dates are `ISODate` strings, never `Date`.** The store round-trips through
  JSON, and `JSON.parse` does not revive Dates — a `Date` field works in dev and
  breaks after a refresh, invisibly to TypeScript. Parse at the render edge.
- **Money is `Cents` (integer).** Divide only when formatting.
- **"Now" is the demo clock, never `new Date()`.** `apiNow()`/`nowIso()` are
  anchored to the seed and never run backwards (a high-water mark persists
  across reloads). Seeded records must not land after `REF_DATE`.
- **`useResource`: skeleton on `isLoading`, never on `isRefreshing`.** Every
  mutation invalidates; gating a skeleton on a refetch blanks the screen.
- **Message delivery status is server-owned.** `lib/mock/delivery.ts` plays
  the carrier; components render status and call `retry()`, nothing more.
- **`@tanstack/react-table` is pinned to `8.21.3`** with a matching `overrides`
  entry. Latest is 9.x, which is a hard API break that every shadcn example and
  most model training data predates. Do not run `shadcn add data-table` — it can
  pull v9 back in. Verify with `npm ls @tanstack/react-table`.
- **shadcn is on Base UI (`style: base-nova`), not Radix.** Composition uses the
  `render` prop, not `asChild`: `<Trigger render={<Button />}>label</Trigger>`.
  Menu labels must sit inside a `DropdownMenuGroup` — a bare
  `DropdownMenuLabel` throws `MenuGroupContext is missing` at runtime.
- **`form` is not used.** react-hook-form integrates through the `Field*`
  components; `FieldError` accepts RHF's errors array directly.
- **Tailwind v4**: no config file, dark mode needs `@custom-variant`, and the
  default border colour is `currentColor` — do not delete shadcn's
  `@layer base { * { @apply border-border } }`.
- **Chart colours are a validated palette, not the preset's.** The `nova` preset
  ships greyscale `--chart-1..5`; `globals.css` replaces them with eight hues
  checked against this project's real light/dark card surfaces for CVD
  separation and contrast. Assign slots in fixed order, never cycled.

## Verifying in the Claude Browser pane

The pane is often **hidden**, which pauses `requestAnimationFrame` and the CSS
animation timeline. Consequences, all harness artifacts rather than bugs:

- enter animations freeze at their first keyframe, so popups read as
  `opacity: 0` and screenshots show them washed out or see-through;
- exit animations never fire `animationend`, so Base UI never unmounts a closed
  popup and a "ghost" menu appears to linger in the DOM.

So: prefer `read_page` / `get_page_text` over screenshots while the pane is
hidden, and do not "fix" animation-state oddities observed there without first
checking `document.timeline` / a `requestAnimationFrame` callback actually
fires.
